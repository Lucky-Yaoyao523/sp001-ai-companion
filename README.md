# SP001 AI Companion · 小胖开源伙伴

**让一台停产的蜘蛛侠，用原来的身体，重新学会中文聊天。**

[English](README.en.md) · [开始体验](#从这里开始) · [开发与集成](docs/integration.md)

它已经有麦克风、扬声器和会动的眼睛。我们想继续用这套硬件，让它听懂新的问题，讲新的故事，接住上一句话，也记得已经确认保存的偏好。

这个项目从一台 Sphero Spider-Man SP001 的原硬件出发，逐步接入中文语音识别、云端对话、流式播报、插话、记忆和家长网页。原型已经在真实玩具上运行；这里公开的是我们编写的源码、离线回归和集成经验。

**当前是开发者源码版。家长网页可以在电脑上启动；玩具端需要适配自己的设备，仓库没有可直接刷入的 APK 或固件。**

## 一台玩具，为什么还值得继续做下去

互动玩具的寿命，往往同时取决于硬件和背后的软件生态。SP001 停产之后，旧应用与服务退出，使重新配置和继续使用变得困难。社区已经在尝试恢复它的使用能力，例如 [Second Life Toys](https://github.com/second-life-toys/second-life-toys) 分享了应用与服务退场后的恢复方案。

我们想继续探索原硬件的中文 AI 交互：保留原主板、麦克风、扬声器、眼睛和外壳，通过 Wi-Fi 接入新的语音与模型服务，让新的对话从这个熟悉的实体里说出来。

一个放在身边、会出声、会有表情的伙伴，带来的互动方式很具体。人可以继续追问，可以改变故事的方向，也可能在它讲到一半时突然想到另一个问题。要接住这些行为，整个声音链路都得跟上。

我们就是从这些要求，一步一步走到现在。

## 第一段路：让原来的身体说中文

先打通一轮完整对话：

```text
原机麦克风 → 轻量客户端 → Wi-Fi → 中文识别与云端模型
                                      ↓
原机扬声器 ← 流式播放 ← 语音合成与回答
```

旧设备负责收音、播放、会话状态和有限的硬件执行，云端负责识别、理解、生成回答及需要的查询。正常聊天可以由玩具经 Wi-Fi 独立完成，电脑上的家长网页是可选组件；云端语音对话仍然需要网络和使用者自己的服务账号。

这条链路接通后，原型可以用中文多轮聊天、讲故事、解释问题和做翻译。当前适配包含 Qwen 识别、MiniMax 对话与语音合成，供应商接口的实现也随源码公开。

接下来，真正麻烦的部分才开始出现。

## 第二段路：把一轮回答，接成可以继续的聊天

真人说话会停顿、补充、纠正，也会中途改变主意。玩具自己的扬声器还会把声音送回麦克风。如果只按“一问一答”去拼接口，这些情况很容易变成抢话、误收音、等得太久，或者旧回答还没停，新问题已经来了。

项目为此保留了收音窗口、回声处理、插话确认、播报取消和会话结束的状态管理。模型继续理解完整请求、决定回答或使用工具；设备端执行受限动作，并把实际结果交回模型。

这里有两个很具体的要求：

- 调音量需要真正执行设备动作，并读取回执。回答中的一句承诺，不能作为执行成功的证明。
- 结束聊天需要真正结束当前聆听。故事角色说了告别台词、用户要求翻译一个词，都要保留原请求的意思。

这些要求形成了正式的工具调用、回执和取消边界。用户反馈过插话体验改善；不同距离、声音和环境下的可靠性仍需要继续实测。

## 第三段路：模型已经答完，玩具为什么没说完

开发中最值得分享的一类问题，是**回答在传递途中丢了**。

调查确认了两个可以复现的缺口：

1. 客户端读到一个合法的回答对象后，忽略了后面继续到来的普通正文。
2. 一轮工具执行结束后，客户端在第一条完成的助手消息处就返回，后续助手消息没有进入回答。

从使用者听来，都是“它怎么突然不讲了”。但要修好，必须分别核对模型实际返回了什么、客户端保留了什么，以及播放端拿到了什么。

我们修正了这两处提前收尾，并把失败形状加入 [正文完整性回归](core-patch/test/NativeReplyCompletenessTest.java)。真实模型的两组文本级接入验证也核对过完整正文；其中工具和播放端使用模拟接口，因此这项证据只证明文本传递，不能代替扬声器实听。

这个过程留下一个很实用的排查方法：**从模型输出一直追到客户端和播放状态，找到正文第一次消失的位置。** 后来出现的取消、网络中断和播放异常仍要分别调查，不能都归到这两处已经修复的缺口上。

## 第四段路：记住偏好，也把使用情况留下来

对话继续久了，就会遇到记忆问题：这轮还能沿用的信息，到了下一轮、下一次启动，究竟还在不在？

项目把当前聊天上下文与本地持久记忆分开处理。稳定偏好可以进入应用私有存储；明确要求保存时，要拿到保存回执，才有依据说已经存下来了。记忆组件也提供查看、删除和档案隔离能力。现有保存与召回机制可以复用，具体事实的长期召回质量仍需持续验证。

另一个变化是增加家长网页。一次聊天发生了什么，不应该只剩下一句笼统的“今天用了多久”。网页可以展示会话、时长、完成或部分回答、工具结果和异常提示；选择保存正文后，才保留相应文字。默认正文保存关闭。

电脑后台暂时关闭时，玩具端可以保留待同步事件。后台恢复后再补传、去重，这条路径已经在原型上做过实测。同步组件使用认证、证书校验和持久游标；迁移后台时也要一起转移记录和游标，一台玩具由一个持久后台负责确认同步。

**电脑后台暂时离线的补传，已经有实测依据；玩具断网期间无法依靠云端继续生成新回答。**

## 现在能实现什么

下面描述的是现有机制及原型范围。公开源码需要接入使用者自己的硬件和账号，表中的语音能力不能直接从下载源码推导为任意玩具都可用。

| 能力 | 实际可以做什么 | 当前依据与边界 |
|---|---|---|
| 中文多轮聊天 | 接着上一轮追问，讲故事、解释问题、翻译 | 原型已运行；事实准确性、专名理解和自然度仍需改善 |
| 流式回答与播报 | 增量接收、分段播放，保留后续正文和工具后的多条消息 | 两处正文丢失已修复并有回归；网络、取消和播放故障仍单独处理 |
| 插话与会话结束 | 确认插话后取消旧播报，管理新一轮收音与结束 | 原型有改善反馈；各种声学环境的可靠性尚未全面验收 |
| 硬件工具与表情 | 查询/调整音量，接入眼睛表情、收音设置和主动接话开关 | 有有限动作和真实回执路径；依赖原运行环境，效果需实机检查 |
| 天气与搜索 | 由模型选择查询，使用结果继续回答 | 接口已提供；天气城市须明确，联网结果仍可能失败 |
| 本地偏好记忆 | 保存、读取、查看和删除偏好，依据保存回执答复 | 有应用私有存储与离线回归；长期准确召回仍需验证 |
| 家长网页 | 查看使用记录、时长、部分回答与异常，配置正文保留周期 | 可本机启动；初始空库，可主动载入合成演示 |
| 记录同步与补传 | 认证读取、持久保存、去重，后台恢复后补齐记录 | 原型有后台停服补传实测；公开版须显式配置自己的配对资料 |
| 使用限制 | 每日时长、次数、安静时段、暂停/恢复，显示指令确认状态 | 软件逻辑与过期拒绝已有验证；有效规则的完整实机执行仍待验收 |

例如，可以围绕下面这些请求设计自己的集成测试：

> 以下是为说明能力新写的示例，不是任何家庭的聊天记录，也不是实测逐字回放。

- “讲一个发生在月球温室里的故事，主角是一只小蜗牛。” → 生成故事，继续承接追问。
- “声音小一档，再告诉我现在是多少。” → 调用设备工具，依据实际回执回答。
- “请记住，我喜欢折纸。” → 尝试保存稳定偏好，依据保存结果回应。
- “明天杭州会下雨吗？” → 明确城市和日期，查询后回答。
- “先停一下，下次再聊。” → 结束当前会话并停止聆听。

当前公开源码有 **95 个 Java 生产源码文件**。发布时编译通过，**57 项 Node 检查、9 组 Java 离线回归通过**。这些数字对应编译和软件回归范围；硬件安装、真人收音、扬声器播放以及多日体验要另外验收。

家长网页和离线 Mock 可以先在电脑上运行。Android 核心依赖原 SP001 运行环境的适配；你也可以研究其中的独立组件，再为其他硬件实现自己的适配层。

## 从这里开始

### 先体验家长网页

安装 [Node.js 22 或更新版本](https://nodejs.org/)，然后：

```sh
git clone https://github.com/Lucky-Yaoyao523/sp001-ai-companion.git
cd sp001-ai-companion
npm start
```

打开终端显示的 `http://127.0.0.1:8787/`，输入本次启动的随机访问码。初次运行是空数据库，可主动载入明确标记的合成演示记录。

Windows 可双击 `START-PARENT.cmd`；Mac/Linux 可运行 `sh START-PARENT.command`。这些入口启动本机网页，Mac 首次运行也需要自行安装 Node.js。

### 再看离线演示和回归

```sh
npm run voice:demo
npm test
npm run check:privacy
```

默认入口不连接玩具，不调用付费模型，不使用麦克风。Java 编译见 [开发说明](docs/development.md)，原硬件接入、自己的配置及同步职责见 [集成说明](docs/integration.md)。

## 接下来还要做好的事

当前仍需改善事实准确性、名称理解、对话自然度、部分回答的取消原因和长会话体验。不同玩具、房间、距离及网络环境的适配，也需要更多真实验证。

欢迎带着一个具体问题参与：一个脱敏后的失败形状、一项能稳定复现的回归、一处硬件适配，或者一段让新人更容易走通的说明。请按 [贡献指南](CONTRIBUTING.md) 删除个人信息后再提交。

这个项目希望让停产设备里的硬件继续被使用，也让做语音伙伴的人能从已经遇到过的问题继续往前走。

## 隐私、公开范围与社区

公开仓库不包含家庭姓名、年龄、所在地、真实对话、记忆、Wi-Fi 资料、设备身份、密钥、私有证书或录音。配置示例关闭且凭据为空；天气没有家庭默认城市。公开副本关闭了 BLE 远程配置和收音启动入口。原型的私有数据与原有工程历史没有进入这份仓库。

公开版没有原厂 APK、拆包资源、角色音频、签名私钥、刷机/恢复工具或调试入口开启步骤。使用自己的合法设备开发环境完成适配。
