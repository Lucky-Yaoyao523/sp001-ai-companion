# SP001 AI Companion · 小胖开源伙伴

**给停产的蜘蛛侠，接上新的中文对话。**

[English](README.en.md) · [能做什么](#它现在能做什么) · [开始使用](#开始使用) · [开发与集成](docs/integration.md)

Sphero Spider-Man SP001 的麦克风、扬声器和眼睛，都装在原来的蜘蛛侠身体里。旧应用与云服务退出后，重新配置和继续使用这套硬件变得困难。这个项目保留原主板与外壳，把中文识别、对话模型和语音合成接进来，让新的回答从原来的扬声器里说出来。

接通声音以后，真正的聊天才开始考验它：故事还在播放，新问题已经来了；模型已经写完，客户端却漏掉后半段；一句“记住了”，还需要核对有没有保存成功。收音、对话、播放和记忆，需要在同一段交流里配合起来。

原型已经在真实 SP001 上运行。这里分享这条链路的自编源码、具体故障的回归测试和可在电脑上体验的家长网页。你可以从一个能读、能运行、能检查的实现开始，继续为自己的设备接上新对话。

> **当前发布：开发者源码版。** 家长网页可在 Windows、Mac 和 Linux 上启动。玩具端需要自己的设备适配和服务账号；本仓库不提供可直接刷入的 APK 或固件。

## 硬件还在，对话可以重新开始

原应用与云服务退场带来的问题，已经有社区在处理。[Second Life Toys](https://github.com/second-life-toys/second-life-toys) 分享了恢复配置和使用能力的工作。我们沿着原硬件继续探索，把中文 AI 对话接到它的收音、播放和表情控制上：

```text
原机麦克风 → 轻量客户端 → Wi-Fi → 中文识别 → 云端对话
                                                    ↓
原机扬声器 ← 流式播放 ← 语音合成 ← 回答与工具结果
```

云端负责识别、理解、生成回答和需要的查询；玩具端管理收音、播放、会话，以及有限的设备动作。现有适配包含 Qwen 识别、MiniMax 对话与语音合成。

配置好的原型可以经 Wi-Fi 独立聊天，无需电脑或手机常驻。家长网页是可选的观察入口。云端对话需要网络连接和使用者自己的服务账号。

## 接通声音之后，才开始遇到真实聊天

故事正在播放，人突然想到另一个问题。客户端需要先确认插话，再停下旧声音、接住新输入。即使上一轮还有迟到的结果，也要按取消状态处理，防止它重新挤进当前对话。

人在说话时还会停顿、补充和纠正。停顿太早被当作结束，一句话就可能没收完；自己的播报被麦克风听见，下一轮就可能收进回声。模型的回答质量之外，什么时候听、什么时候说、什么时候停，也决定了交流能不能继续。

项目围绕这些场景加入了收音窗口、回声处理、插话确认、旧播报取消和会话结束管理。原型使用中已有插话改善的反馈，更多距离、声音和房间条件仍需验证。

设备动作也需要落到实际结果上。比如调低音量，流程要经过模型工具请求、设备执行和结果回传。模型收到执行回执，才能依据结果继续说话。理解用户的意思、选择查询和组织回答由模型负责；客户端处理传输、生命周期、资源边界和有限设备执行。

## 一次“怎么不讲了”，追到了两处丢失的正文

开发中，一类特别容易误判的问题是回答突然变短。听起来像模型只写了几句话，实际缺口却可能在回答传递的途中。

公开回归用一段海洋馆介绍构造了这个场景：开头是“我们把海洋馆分成两个区域。”，后面还有水池分隔、参观通道和入口流程。旧逻辑在开头之后过早收尾，后面的介绍没有完整交付。这是测试中的构造文本，并非家庭对话回放。

沿着供应商输出、客户端接收和播放输入逐段核对，我们确认了两处可以复现的缺陷：

- **回答对象后的文字被漏掉。** 客户端解析到一个合法的回答对象，后面继续到来的普通正文没有进入最终回答。
- **工具后的回答提前收尾。** 工具执行完成后，客户端拿到第一条完成的助手消息就返回，遗漏了后续助手消息。

这两处都能让一段已经生成的内容，只传到玩具一部分。修复后，客户端继续保留后续正文，也继续接收符合条件的工具后消息。失败场景保存在 [正文完整性回归](core-patch/test/NativeReplyCompletenessTest.java) 中，后续修改可以重新检查。

两组真实模型的文本级接入验证核对了完整正文；工具和播放接口使用模拟，因此扬声器实际播报还需要单独验收。取消、网络中断和播放异常也有各自的原因，仍须分别调查。

这次排查留下了一个可以复用的方法：**把模型给出的内容、客户端接住的内容和播放拿到的内容放在一起，找到文字第一次消失的位置。** 做语音设备的人，往往也会遇到这条链路上的问题。

## 聊天之后，记忆和记录也要接得住

能承接当前追问之后，下一个需求自然出现：下次启动，已经保存的偏好还在吗？

项目将当前聊天上下文与本地持久记忆分开。偏好可以保存在应用私有存储中，并支持查看、删除和档案隔离。明确要求保存时，需要拿到保存结果，再据此答复。这里公开了保存和召回机制；具体事实在长期使用中能否准确召回，仍需持续验证。

家长网页则帮助人看见聊天的过程：用了多久，有哪些会话，回答是完成还是部分播出，工具有没有返回结果，异常发生在哪一轮。正文是否保存、保留多久由使用者选择，默认关闭正文保存。

我们在原型上测试过一次完整过程：停止电脑网页服务，玩具仍经 Wi-Fi 完成云端聊天；恢复服务后，暂停期间留下的事件补齐，没有重复记录。后台暂时不可用时，玩具端的持久事件让同步能够接着进行。

同步采用认证、证书校验和持久游标；迁移时要一起转移记录和游标，并让一个持久后台负责确认同一台玩具的同步。玩具本身断网时，无法继续依靠云端生成新回答。

这些记录让故障更容易追查，也让使用者能决定哪些内容应该留下、何时删除。

## 它现在能做什么

下表描述现有组件和配置好的原型。使用公开源码接入玩具，需要自行完成硬件适配。

| 你想做的事 | 项目提供的能力 |
|---|---|
| 用中文聊下去 | 多轮上下文，故事、解释、翻译，以及后续追问 |
| 一边生成，一边播报 | 增量接收、分段播放，保留续传正文和工具后的多条助手消息 |
| 中途插话或结束聊天 | 插话确认、旧播报取消、新一轮收音和会话结束管理 |
| 让请求变成设备动作 | 音量查询与调整，眼睛表情、收音设置和主动接话开关的适配入口；按实际执行结果回传 |
| 查询天气或资料 | 模型选择天气与搜索工具，用查询结果继续回答；天气须明确城市 |
| 保存稳定偏好 | 本地保存、读取、查看、删除和档案隔离，返回保存结果 |
| 看见使用情况 | 本地家长网页，展示会话、时长、部分回答、工具结果和异常，提供正文保留设置 |
| 服务恢复后补齐记录 | 认证同步、持久事件与游标、去重和补传 |
| 配置使用规则 | 每日时长、次数、安静时段、暂停与恢复，以及指令确认状态；完整实机执行仍待验收 |

下面是新写的能力示例，**并非家庭真实对话，也不是实测回放**：

- “讲一个月球温室里的故事，主角是一只小蜗牛。” 接着可以补充：“让它遇见一位新朋友。”
- “声音小一档，再告诉我现在是多少。” 让一次工具执行和结果回答连起来。
- “请记住，我喜欢折纸。” 依据保存结果回应，再测试后续召回。
- “明天杭州会下雨吗？” 带明确城市和日期查询。
- “先停一下，下次再聊。” 结束当前会话。

## 为什么把这些代码公开

做实体语音伙伴，需要把几件事同时接好：声音要收完整，回答要传完整，工具要真实执行，取消要能停下，记录要能解释发生了什么。

这份仓库把这些环节放在同一个参考实现里，也留下已经遇到的失败场景。你可以先运行家长网页和离线演示，再阅读某一个组件，为自己的设备实现适配。

**如果你有 SP001**，这里可以研究中文对话的接入方式。**如果你在做其他语音硬件**，回答流、工具结果、会话取消、记忆和日志同步也可以提供参考。原机 `Owner*` 适配层依赖 SP001 的运行环境，移植时需要替换对应部分。

| 从哪里开始研究 | 代码入口 |
|---|---|
| 模型请求与工具定义 | [NativeDialogueProtocol](core-patch/src/org/sp001/core/NativeDialogueProtocol.java) |
| 流式回答与正文完整性 | [NativeDialogueEngine](core-patch/src/org/sp001/core/NativeDialogueEngine.java)、[ReplyEnvelopeStream](core-patch/src/org/sp001/core/ReplyEnvelopeStream.java) |
| 收音、播报与插话 | [OwnerNativeConversation](core-patch/src/org/sp001/core/OwnerNativeConversation.java)、[OwnerDuplexCapture](core-patch/src/org/sp001/core/OwnerDuplexCapture.java) |
| 本地偏好记忆 | [CompanionMemory](core-patch/src/org/sp001/core/CompanionMemory.java)、[OwnerCompanionMemory](core-patch/src/org/sp001/core/OwnerCompanionMemory.java) |
| 持久事件与记录补传 | [ParentJournalState](core-patch/src/org/sp001/core/ParentJournalState.java)、[toy-pull.mjs](parent-console/toy-pull.mjs) |
| 家长网页 | [parent-console/](parent-console/) |

## 开始使用

### 在电脑上体验家长网页

安装 [Node.js 22 或更新版本](https://nodejs.org/)，下载或克隆源码，然后运行：

```sh
git clone https://github.com/Lucky-Yaoyao523/sp001-ai-companion.git
cd sp001-ai-companion
npm start
```

打开终端显示的本机网址，通常为 `http://127.0.0.1:8787/`，输入本次启动的随机访问码。数据库初始为空，可以主动载入明确标记的合成演示记录。

安装 Node.js 后，Windows 也可双击 `START-PARENT.cmd`；Mac/Linux 可运行 `sh START-PARENT.command`。

### 运行离线演示，或接入自己的设备

```sh
npm run voice:demo
npm test
npm run check:privacy
```

默认演示和检查不连接玩具、不使用麦克风、不调用付费模型。Java 编译见 [开发说明](docs/development.md)；玩具运行环境、自己的账号配置与同步职责见 [集成说明](docs/integration.md)。

## 目前走到了哪里

原型已在真实硬件上运行中文对话，电脑后台停服后的记录补传有实测依据。两处正文丢失问题有复现、修复和回归，也做过真实模型的文本级完整性核对。

首个源码版本编译了 **95 个 Java 生产源码文件**，通过 **57 项 Node 检查和 9 组 Java 离线回归**。这些检查覆盖编译和软件行为。

接下来仍要改善事实准确性、专名理解、自然对话、部分回答的取消原因和长会话体验。插话在不同环境下的可靠性、修复后的扬声器完整播报、长期记忆召回，以及有效家长规则的完整实机执行，都需要各自的实际验证。当前源码也需要使用者为自己的设备完成适配。

欢迎贡献一个可以复现的问题、一项回归测试、一个硬件适配，或一段更容易走通的说明。提交前请按 [贡献指南](CONTRIBUTING.md) 删除个人资料和凭据。

我们希望，别人再把一段新对话接进一台旧设备时，能够从这里继续往前走。

## 隐私与发布范围

公开仓库没有家庭身份、年龄、所在地、真实对话、家庭记忆、Wi-Fi 资料、设备身份、凭据、私有证书或录音。配置示例关闭且凭据为空；正文保存默认关闭，没有接入自动云总结。公开副本关闭 BLE 远程配置和收音启动入口，私人数据及原工程历史没有导出。
